\subsection{EUROCAE ED-117}
\label{sec:appendix_eval_std_ed117}

The 'EUROCAE ED-117' standard covers the MOPS for Mode S multilateration systems intended for airport surface surveillance, and is mapped from the edition of January 2004. \\

The performance requirements of the source document address Mode S transmitting targets. The standard therefore sets 'Ignore Primary Only Targets', see the 'Standard' tab of the Evaluation dialog. Mode A/C-only targets are not excluded, since the 2004 edition does not state the restriction in the same form as the later edition. If the assessed system is expected to report Mode A/C-only targets as well, 'Ignore Mode A/C Only Targets' may be set in addition. \\

\subsubsection{Implementation Notes}

\begin{itemize}
\item \textbf{Identification split into three requirements.} The source document states one figure for the correct identity. The identity under assessment consists of the 24-bit address, the Mode 3/A code and the aircraft identification. Three instances are configured, one per item, each carrying the stated figure. A missing Mode 3/A code or aircraft identification counts as not correct, so these two instances also measure presence. A single instance with 'Require Correctness of All' set gives the combined figure instead, if that reading is preferred.
\item \textbf{Detection method.} The detection instances use the status message method, see \nameref{sec:eval_req_detection}. Where the system under test reports its update cycles, the expected periods are taken from those cycles rather than from a nominal cadence. Where it does not, the time difference method applies, with a miss tolerance of 0.5 s to cover the cadence jitter of an event driven multilateration output.
\item \textbf{Stand position accuracy.} The source document states this requirement on an averaged position over a 5 s period. The 'Use Averaging' option of the Position Distance requirement implements it. The document states no confidence level for it, so the configured probability is 100\%, meaning every averaging window has to pass.
\item \textbf{Maneuvering area.} ICAO defines the maneuvering area as runways plus taxiways. Both the update and the detection requirement are therefore held in one group, rather than in separate runway and taxiway groups.
\item \textbf{False identification period.} The source document states this requirement over a 5 s period per target. The Identification False requirement counts per target report. The configured value is therefore an approximation, and is noted as such in the requirement comment.
\item \textbf{False detection.} The definition of a false target report in the source document also covers spurious reports. Only the outlier part is configured, since the site test procedure of the document measures that part with a test vehicle. The \nameref{sec:eval_req_extra_data} requirement can be added to cover the spurious part, at the cost of a second figure that has to be added by hand.
\end{itemize}

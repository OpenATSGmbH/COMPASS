    \item Line ID: Line ID to be used
    \end{itemize}
\item Data Timeframe: Time window of data to be processed
    \begin{itemize}
    \item Begin / End timestamps
    \end{itemize}
\item Data Slicing: Time slice sizes
    \begin{itemize}
    \item Slice Length: Duration of a time slice
    \item Slice Overlap Length: Duration of an overlap region to "glue" slices together
    \end{itemize}
\item Delete All Calculated Reference Trajectories: If active, all previous calculated references are deleted
\item Skip Writing of Reference Trajectories: If active, calculated references and associations are not written into the database
\end{itemize}

Please also \textbf{note} that for ground surveillance datasets containing \textbf{SMRs}, it is imperative to set the detection type to "Primary Only" as well as to enable the "Ground Only" checkbox. Otherwise, SMR plots will be associated over long distances and cause sub-optimal reconstructor results.

\subsubsection{Sectors}

In the 'Sectors' tab, an optional spatial filter can be applied to the data used for reconstruction. When active, only target reports whose position falls inside at least one of the selected sector layers (extended outward by a configurable surrounding delta) are admitted to reconstruction; the remaining target reports are discarded. This can be used to limit reconstruction to a defined operational volume of interest. \\

\begin{figure}[H]
  \centering
      \hspace*{-1.0cm}
      \includegraphics[width=17cm]{figures/dialog_sectors.png}
  \caption{Reconstructor: Sectors tab}
\end{figure}

The following controls exist:

\begin{itemize}
\item Use Sectors: When checked, the spatial filter is active. The checkbox is only enabled if at least one sector layer is defined in the active Data Context (see \nameref{sec:ui_configure_sectors}).
\item Sector Layer Checkboxes: One checkbox per available sector layer; only checked layers participate in the inside test.
\item Surrounding Delta [WGS84 deg]: Tolerance in WGS84 degrees added around the sector polygons (default 0.1 deg). A target report just outside a sector boundary is still kept if its position is within this delta of the polygon.
\end{itemize}
\ \\

Every target report is tested against the polygons of the selected sector layers, grown outward by the surrounding delta. Target reports falling inside at least one of these layers (or within the delta of its boundary) are admitted to reconstruction; all others are discarded. The delta acts as a tolerance band around the sector edges, ensuring that targets crossing a boundary still have enough surrounding target reports to be associated cleanly. \\

Please also \textbf{note} that the same 'Sectors' tab is available in both the Scoring + UMKalman and the Probabilistic + IMM configuration, with identical behavior. \\

\subsubsection{Classification}

In the classification tab, special parameters can be set to identify the AnyAircraft and Vehicle categories. Any target (without any other class information) and any Mode C code above the given 'Minimum Aircraft Altitude' will be classified as AnyAircraft. Vehicles (without any other class information) can be set by giving a list of Mode S Aircraft Identification and/or Aircraft Addresses. \\

    \label{tab:reconst_params}

Result resampling is enabled in order to obtain reference trajectories with a homogeneous sample rate. 
It is carried out by interpolating the Kalman states at fixed time-steps. The accuracy of the resulting samples
follows the Kalman accuracies more closely when interpolating near the endpoints of a segment, and it will decrease
in the middle of a segment. The amount of decrease of accuracy will depend on the time duration of the segment and the used 
process standard deviation (parameter \textit{Resample Process Stddev}).

\paragraph{Parameter Usage}

Association of target reports to UTNs:
\begin{itemize}
\item Maximum Comparison Time Difference: Maximum time difference for Mode A/C comparisons
\item Maximum Track Time Difference: Maximum time difference to re-use previous system track to UTN associations
\item Maximum Acceptable Distance (Ground/Air): Maximum distances for allowed associations
\item Maximum Altitude Difference: Maximum Mode C difference for allowed associations
\end{itemize}
\ \\

Self-associate new targets (find matching UTNs created by the same target):
\begin{itemize}
\item Maximum Comparison Time Difference: Maximum time difference for Mode A/C comparisons
\item Maximum Distance (Ground/Air)
\begin{itemize}
\item Acceptable/Dubious/Erroneous: Each type of distance is counted
\item If too many Erroneous (5-10\%): Not associated
\item If too many Dubious (30-50\%): Not associated
\item If Acceptable: Consider as match
\item Association of targets is made for best matches fulfilling an average position difference score
\end{itemize}
\item Minimum Updates: Minimum number of updates needed to consider a match
\item Minimum Time Overlap Probability: Minimum time overlap probability for at least one of the targets to consider a match
\end{itemize}

Primary Only Mode has the following options:
\begin{itemize}
    \item \textbf{Probabilistic Scoring}: Primary plots are associated to existing targets using probabilistic distance measures at the end of a calculation pass. Tentative target creation will be disabled.
    \item \textbf{JPDA + Probabilistic Scoring}: Primary plots are associated using JPDA. JPDA may associate them to existing targets or initiate new tentative targets with them, otherwise they will be re-associated to existing targets using probabilistic distance measures at the end of a calculation pass.
\end{itemize}
\ \\

Write Radar Biases/Accuracies controls how the estimated radar biases and accuracies are persisted back to each radar Data Source in the active Data Context (see \nameref{sec:reconst_radar_bias_estimation}). The setting is only effective when 'Correct Radar Biases' is enabled. The following options exist:

\begin{itemize}
    \item \textbf{Set if Missing}: Only set values on radar Data Sources that do not yet carry a bias / accuracy entry; existing values are left untouched.
    \item \textbf{Merge}: Open a side-by-side review dialog after the run, where the user can accept or reject each proposed change per Data Source before it is applied.
    \item \textbf{Override}: Always overwrite the existing values with the latest estimates.
    \item \textbf{Do Nothing}: Discard the estimates; the active Data Context is not modified.
\end{itemize}
\ \\

Please \textbf{note} that:
\begin{itemize}
\item All of the features above \textit{should} work as intended with the given default values
\item Should this not be the case, disabling of certain features can be a valid workaround until the issue is resolved by a bugfix
\item Use Risky ADS-B: This feature will allow usage of MOPS V0 and V1 transponders, as well as position data with unknown accuracy
\begin{itemize}
\item While accuracy determination algorithms will automatically determine usage of such "risky" ADS-B data, absolute correctness can not be guaranteed in all situations
\item Usage of this feature is therefore disabled by default, and activation should always be accompanied with manual verification of the reconstruction results
\end{itemize}
\item Do Full Primary-Only Tracking: This will commonly increase computational requirements by factor 3-5. Can be disabled for large datasets or slower workstations, at cost of primary-only reconstruction quality.
\end{itemize}

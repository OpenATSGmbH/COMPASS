The 'Identification Correct' requirement is used to calculate the probability of a target report having a correct (secondary) identification. Correct in this context means there is identification data available, 
and it is the same as in the reference. \\

\begin{itemize}  
\item Probability [1]: Probability of correct identification
\item Probability Check Type: $\geq$
\item Require correctness of All: If checked, all available secondary attributes must match the reference. If not checked, a single matching secondary attribute is enough.
\item Use Mode 3/A Code: If the Mode 3/A code should be checked
\item Use Mode S Target Address: If the Mode S target address should be checked
\item Use Mode S Target Identification: If the Mode S target identification should be checked
\end{itemize}

\subsection{Identification Correct Periods}
\label{sec:eval_req_id_correct_periods} 

\subsubsection{Configuration}

\begin{figure}[H]
    \centering
    \includegraphics[width=14cm,frame]{figures/eval_req_id_correct_periods.png}
  \caption{Evaluation Identification Correct Periods requirement}
\end{figure}

This requirement calculates the probability of correct aircraft identification detection. \\

For each target existing in the reference data (within the current sector) a test target's identification should
be detected correctly within each test update interval. Correctly here means equality.
Update intervals without correct identification are counted as misses, which are used to calculate the probability of correct aircraft
identification detection, which has to fulfill a given threshold.

\begin{itemize}
    \item Probability [1]: Probability of correct aircraft identification detection
    \item Probability Check Type: $\geq$
    \item Update Interval [s]: Update interval of the test data
    \item Use Miss Tolerance: Checkbox if miss tolerance should be used
    \item Miss Tolerance [s]: Acceptable time delta for miss detection
    \item Identification Type: Type of identification to check (\textit{Aircraft Address}, \textit{Aircraft Identification} or \textit{Mode A})
\end{itemize}

\subsection{Identification Change Delay}
\label{sec:eval_req_id_change_delay}

\subsubsection{Configuration}

\begin{figure}[H]
    \centering
    \fcolorbox{red}{white}{\parbox[c][4cm][c]{12cm}{\centering \textcolor{red}{\textbf{[TODO: screenshot figures/eval\_req\_id\_change\_delay.png: Identification Change Delay requirement configuration]}}}}
  \caption{Evaluation Identification Change Delay requirement}
\end{figure}

The 'Identification Change Delay' requirement is used to check how fast a change of the aircraft identification (Aircraft ID) or the Mode 3/A code is reported by the test data with the new, correct value. It implements the change delay recommendation of EUROCAE ED-129C section 3.3.1 (REC 495). \\

The delay is measured from the final value set in the reference data to the first test target report carrying that value. Transitional Mode 3/A codes (as transmitted by some control heads during code entry) are ignored: a new reference value only counts as a change event when it stays stable for a configurable minimum time. \\

\begin{itemize}
\item Probability [1]: Probability of acceptable change delay
\item Probability Check Type: $\geq$
\item Identification Type: Type of identification to check (\textit{Aircraft ID} or \textit{Mode A})
\item Maximum Delay [s]: Maximum acceptable delay from the final reference value change to the first test report with the new value
\item Minimum Stable Time [s]: Minimum time a new reference value must hold to count as a change event (transitional code filter)
\end{itemize}
\ \\

\subsubsection{Calculation}

The reference identification values are checked over time. A new value becomes stable when it holds for at least the 'Minimum Stable Time [s]'. Each stable value after the first one defines a change event, with the event time of the first reference target report carrying the new value. Only events inside the sector layer are used. \\

For each change event, the first test target report at or after the event time with the new value is searched:
\begin{itemize}
\item If found, the change delay is the time from the event to that test target report. The event passes if the delay is within the 'Maximum Delay [s]' (\#CDOK), otherwise it fails (\#CDNOK).
\item If the new value is never reported and enough test data time (at least the maximum delay) remained after the event, the event fails.
\item If the new value is never reported and the test data ends less than the maximum delay after the event, the event is counted as not assessable and counts neither as passed nor as failed.
\end{itemize}
\ \\

The Probability of Acceptable Change Delay is the ratio of \#CDOK to the number of assessed events. It must fulfill the given 'Probability' condition for the requirement to pass. For a strict check per EUROCAE ED-129C TABLE 4 (each change within 15 s for the 3NM service, within 24 s for the 5NM service), the probability is set to 1. \\
